## 1. 系统架构

### 1.1 整体架构

DCP 评审中心基于 ONES 插件平台，支持 DCP（Decision Checkpoint，阶段决策评审）和 TR（Technical Review，技术评审）两种评审类型，采用"前端模块 + 后端 API + 实体存储"三层架构：

```
┌──────────────────────────────────────────────────────────────┐
│                        ONES 平台宿主                            │
│  ┌─────────────┐  ┌──────────────┐  ┌─────────────────────┐  │
│  │ 项目内组件    │  │  评审人工作台   │  │   侧边栏应用容器      │  │
│  │dcp-review-tab│  │dcp-reviewer-  │  │   dcp-sidebar       │  │
│  │(ProjectCustom│  │workspace      │  │ ┌─────────────────┐ │  │
│  │ Component)   │  │(ones:workspace│  │ │dcp-template-config│ │  │
│  │              │  │ :new)         │  │ │dcp-review-overview│ │  │
│  └──────┬───────┘  └──────┬────────┘  │ └────────┬────────┘ │  │

│  ┌──────────┐ ┌──────────┐ ┌──────────┐ ┌──────────────────┐  │
```

### 1.2 ONES 插件平台集成方式

| 集成能力 | 类型 | 说明 |
|---------|------|------|
| **External API** | `type: external` | 后端通过 `apis` 段注册 47 个 REST 端点，前端通过 `/project/api/project/team/{teamUUID}` 前缀路由访问，需携带 `Ones-Plugin-Id` 请求头 |
| **Entity Storage** | `storage.entities` | 声明 15 个自定义实体表，使用 `storage.entity(name)` 获取句柄，支持 `.get()/.set()/.delete()/.query()` 操作 |
| **SidebarMenu** | `abilityType: SidebarMenu` | 注册侧边栏菜单入口 `dcp-sidebar`，包含「模板配置」和「评审总览」两个子页面 |
| **ProjectCustomComponent** | `abilityType: ProjectCustomComponent` | 注册项目自定义组件 `dcp-review-tab`，可作为项目页签嵌入项目内；声明 `copyPluginData` 钩子（返回不复制） |
| **事件订阅** | `ones:project:issue-status:changed` | 监听整改工作项状态变化，回写服务端校验后的权威状态并在全部完成时通知决议人和创建者 |
| **OPFetch** | `@ones-op/fetch` | 后端通过 OPFetch 调用 ONES 内部 API（项目元数据解析、工作项创建、工作项类型查询、工作项状态查询），自动携带团队鉴权 |
| **Notify** | `@ones-op/node-ability` | 通过 Notify 能力发送通知，支持邮件(Email)、微信(WeChat)、钉钉(DingDing)、飞书(Lark)、有度(YouDu) 五种渠道 |
| **微前端容器** | `__ONES_MF_ENV__` | 前端从 ONES 微前端环境变量获取 teamUUID、pluginID、instanceId 等上下文 |

### 1.3 运行模式

- `service.mode: org` — 团队级插件，数据按团队隔离
- `service.scope: 1` — 组织级作用域
- `service.language: nodejs` — Node.js 运行时
- 最低系统版本 `3.11.39`，host 版本 `1.11.33`

## 2. 模块划分

### 2.1 模块总览

| 模块 ID | 模块类型 | 入口文件 | 职责 |
|---------|---------|---------|------|
| `dcp-review-tab` | `ones:project:component:new` | `./modules/dcp-review-tab/index.tsx` | 项目内 DCP/TR 评审工作台 |
| `dcp-reviewer-workspace` | `ones:workspace:new` | `modules/dcp-reviewer-workspace/index.html` | 评审人工作台 |
| `dcp-sidebar` | `ones:app:new` | — | 侧边栏应用容器 |
| `dcp-template-config` | 子模块(dcp-sidebar) | `modules/dcp-sidebar/dcp-template-config/index.html` | 模板配置页（转发 dcp-config-page） |
| `dcp-review-overview` | 子模块(dcp-sidebar) | `modules/dcp-sidebar/dcp-review-overview/index.html` | 评审总览页（转发 dcp-team-overview） |

> 注：`dcp-template-config` 和 `dcp-review-overview` 入口仅 5 行，分别转发至 `dcp-config-page/index.tsx`（968 行）和 `dcp-team-overview/index.tsx`（658 行）。

### 2.2 各模块详细说明

#### 2.2.1 dcp-review-tab（项目内评审组件）

- **类型**：`ones:project:component:new`（项目自定义组件）
- **权限**：无单独权限点，跟随项目访问权限
- **职责**：在项目页面内以页签形式展示评审工作台，是创建和管理评审单的主入口
- **源文件**：`index.tsx`（2919 行）+ `api.ts`（152 行）+ `RemediationPanel.tsx`（187 行）+ `RoundCompare.tsx`（241 行）
- **核心功能**：
  - 评审列表展示（分页，按视口高度自适应每页 5~15 条）
  - 创建评审单（选择评审类型 DCP/TR、选择阶段、填写标题、会议时间）
  - 评审详情（8 个 Tab：评审资料/指标/评审人/工作项/Checklist/决议/审计/轮次对比）
  - 材料上传/下载/预览（预签名 URL 直传对象存储）
  - 评审人维护、发起评审（三重校验）
  - 评审撤回（recallReview）
  - 整改闭环管理（RemediationPanel）
  - IPD 流程图展示
  - 评审单直链复制（构建指向 dcp-review-overview 的深链接）
- **前端上下文获取**：从 `window.parent.location.hash` 解析 `projectUUID/projectKey/componentUuid/viewUuid`，通过 exchange API + stamps API 补查项目名称

#### 2.2.2 dcp-reviewer-workspace（评审人工作台）

- **类型**：`ones:workspace:new`
- **职责**：评审人的个人工作台，展示待办/已办评审，支持提交评审意见
- **核心功能**：
  - 待评审 / 已评审 Tab 切换
  - 评审详情查看（材料、指标、其他评审人意见、checklist）
  - 提交评审意见（结论 pass/conditional_pass/reject、风险等级、意见摘要）
  - 深链接直达（`?review_uuid=xxx`）
  - checklist 勾选（按角色匹配）
  - 创建/关联工作项
  - 整改项管理（整改闭环阶段）

#### 2.2.3 dcp-review-overview → dcp-team-overview（团队评审总览）

- **类型**：dcp-sidebar 子模块，权限点 `dcp_view_review`
- **职责**：团队级评审全景视图，汇总所有项目的评审数据
- **源文件**：`dcp-team-overview/index.tsx`（658 行）
- **核心功能**：
  - 统计卡片（总评审数、评审中、已完成、关联工作项数、通过率）
  - 评审列表（可排序、可按项目折叠分组）
  - 评审详情（复用 dcp-review-tab 的 ReviewDetail 组件）
  - 项目名称前端兜底补查（hydrateProjectNames）
  - 深链接直达 + 编号链接复制
  - 时间范围筛选（本周/本月/本季度/本年/全部 + 自定义日期范围）

#### 2.2.4 dcp-template-config → dcp-config-page（模板配置）

- **类型**：dcp-sidebar 子模块，权限点 `dcp_admin`
- **职责**：全局评审模板配置，管理员维护十类配置
- **源文件**：`dcp-config-page/index.tsx`（968 行）
- **配置项**（左侧导航 10 个 Tab）：
  - **阶段模板**（phases）：DCP1~DCP5 / TR1~TR6 阶段、决议选项、决议模板、依赖关系、review_type
  - **材料模板**（materials）：材料名称、适用阶段、是否必交、负责角色、review_type
  - **指标模板**（indicators）：指标名称、适用阶段、单位、阈值类型、黄/红阈值
  - **评审角色**（roles）：角色名称、是否必投(must_vote)、是否否决(has_veto)、review_type
  - **Checklist 模板**（checklist）：检查项文本、适用阶段、负责角色
  - **决议规则**（resolution）：按 DCP/TR 分别配置——发布人角色、提交要求模式、允许的结论、通过规则
  - **通知设置**（notify）：启用开关、三个触发点、五种渠道
  - **IPD 流程图**（ipdflow）：阶段布局和 DCP/TR 标记位置
  - **撤回配置**（recall）：撤回时间窗口和权限
  - **整改配置**（remediation）：整改工作项类型配置
- **编辑机制**：编辑态开关控制，保存时后端先删除旧记录再全量写入（replace 策略）

#### 2.2.5 dcp-sidebar（侧边栏容器）

- **类型**：`ones:app:new` + `abilityType: SidebarMenu`
- **职责**：通过 SidebarMenu 能力注册左侧导航入口，承载 dcp-template-config 和 dcp-review-overview 两个子页面

## 3. 后端 API 设计

后端共注册 47 个 external API 端点（`plugin.yaml` 的 `apis` 段），全部定义在 `backend/src/index.ts`（4452 行）中。所有端点路由前缀为 `/project/api/project/team/:teamUUID`，需携带 `Ones-Plugin-Id` 请求头。

### 3.1 配置管理 API

| # | 方法 | 路径 | Handler 函数 | 功能说明 |
|---|------|------|-------------|---------|
| 1 | GET | `/dcp/config` | `getDcpConfig` → `getPluginConfig` | 获取全局配置：阶段/材料/指标/角色/checklist 模板 + 通知配置 + 撤回配置 + 决议规则 + IPD 流程布局 + 整改配置 |
| 2 | POST | `/dcp/config` | `savePluginConfig` | 保存全局配置，先删旧记录再全量写入；决议规则保存前做可达性校验 |

### 3.2 评审单管理 API

| # | 方法 | 路径 | Handler 函数 | 功能说明 |
|---|------|------|-------------|---------|
| 3 | POST | `/dcp/review` | `createReview` | 创建评审单，支持 review_type（dcp/tr），自动带出适用阶段的材料/指标模板，生成编号 `{项目标识}{YYYYMMDD}{两位序号}` |
| 4 | GET | `/dcp/review/:review_uuid` | `getReviewDetail` | 获取评审单聚合详情（评审单+材料+指标+评审人+关联工作项+决议+补充说明+checklist+轮次信息） |
| 5 | GET | `/dcp/reviews/by-project/:project_uuid` | `listReviewsByProject` | 按项目列出评审单，含评审人完成情况/材料进度/关联工作项数 |
| 6 | GET | `/dcp/reviews` | `getDcpReviews` | 别名路由，带 `project_uuid` 参数时转发到 `listReviewsByProject`，否则转发到 `listTeamReviews` |

| 8 | GET | `/dcp/reviews/team` | `listTeamReviews` | 团队全部评审，含统计数据（总数/评审中/已完成/关联工作项数），批量解析项目元数据 |

| 13 | POST | `/dcp/review/:review_uuid/copy` | `copyReview` | 复制评审单（草稿状态，复制材料/指标/评审人） |
| 14 | POST | `/dcp/review/:review_uuid/transition` | `transitionReview` | 评审单状态流转（基于决议规则配置的通用转换接口） |
| 15 | GET | `/dcp/review/:review_uuid/state` | `getReviewState` | 获取评审单当前状态和有效状态（effective_state） |
| 16 | GET | `/dcp/review/:review_uuid/rounds` | `getReviewRounds` | 获取评审单的轮次信息 |

## 5. 关键技术实现

### 5.1 实体存储与分页

#### qAll cursor 分页机制

ONES Entity Storage 的 `getMany()` 方法硬限制每页最多返回 200 条记录。系统封装了通用 `qAll()` 函数实现自动游标分页：

```typescript
async function qAll(e: any, filter?: (v: any) => boolean) {
  const allItems: any[] = []
  let cursor: string | null = null
  let safety = 0
  while (safety < 100) {           // 安全阀：最多 100 页 = 20000 条
    safety++
    const q = e.query().limit(200)
    if (cursor) q.cursor(cursor)
    const result = await q.getMany()
    if (!result || !Array.isArray(result.data)) break
    for (const d of result.data) {
      allItems.push({ _key: d.key, ...(d.value || {}) })
    }
    const pi = result.page_info
    if (pi && pi.has_more && pi.end_cursor) {
      cursor = pi.end_cursor
    } else {
      break
    }
  }
  return filter ? allItems.filter(filter) : allItems
}
```

- **安全阀**：最多循环 100 次（20000 条）
- **内存过滤**：entity storage 不支持服务端条件过滤，`qAll` 先全量拉取再在内存中按 filter 函数过滤

#### 父实体 JSON 快照兜底

系统采用多级快照策略防止子实体查询丢失：

1. **reviewers_json**：`updateReviewers` 写子实体同时写父实体快照，读取时优先读快照
2. **checklist_json**：`startReview` 时从模板初始化到父实体快照，后续直接操作快照字段
3. **indicators_json / materials_json**：指标和材料数据的快照
4. **checklist_templates_json**：发起评审时冻结 checklist 模板配置
5. **_frozen**：发起评审时冻结全局模板配置（阶段/材料/指标/角色模板），确保评审进行中不受后续配置变更影响
6. **submitOpinion 同步快照**：每次提交评审意见后同步更新 `reviewers_json`

### 5.2 评审流程状态机

#### 11 种状态

```
draft, ready, reviewing, awaiting_resolution, resolution_published,
remediation_pending, re_reviewing, completed, rejected, canceled, archived
```

#### 状态流转

| From | To | 触发条件 |
|------|-----|---------|
| `draft` | `ready`, `reviewing`, `canceled` | 发起评审/取消 |
| `ready` | `reviewing`, `draft`, `canceled` | 开始评审/退回/取消 |
| `reviewing` | `awaiting_resolution`, `remediation_pending`, `draft` | 全部提交/需整改/撤回 |
| `awaiting_resolution` | `resolution_published`, `reviewing` | 发布决议/退回 |
| `resolution_published` | `completed`, `remediation_pending` | 决议完成/需整改 |
| `remediation_pending` | `re_reviewing` | 全部整改项完成后发起复审 |
| `re_reviewing` | `awaiting_resolution`, `remediation_pending` | 复审完成/需再次整改 |
| `completed` | `archived` | 归档 |

#### getEffectiveState

`getEffectiveState(rv)` 从 `rv.status` 派生有效状态：
- `draft` → `draft`
- `reviewing` → `reviewing` / `awaiting_resolution` / `re_reviewing`（根据评审人提交情况和轮次判断）
- `completed` → `completed`
- `rejected` → `rejected`

### 5.3 决议规则配置

系统支持按 DCP 和 TR 分别配置决议规则（`resolution_rule_config`），存储在 `dcp_base_config` 表中。

#### 配置结构

```json
{
  "dcp": {
    "publisherRole": "Chair",
    "submitRequirement": {
      "mode": "must_vote_roles | all_reviewers | vote_scope_roles | publisher_only"
    },
    "allowedConclusions": ["pass", "conditional_pass", "reject"],
    "passRule": {
      "rejectOnAnyVeto": true,
      "minPassVotes": 3
    }
  },
  "tr": { /* 同结构 */ }
}
```

#### publishResolution 校验逻辑

1. **操作人校验**：必须是决议规则中 `publisherRole` 指定的角色评审人
2. **状态校验**：`rv.status === 'reviewing'`，effective_state 在 `reviewing/awaiting_resolution/re_reviewing`
3. **结论校验**：`final_conclusion` 必须在 `allowedConclusions` 列表中（支持中文→英文映射：通过→pass 等）
4. **提交要求校验**（按 `submitRequirement.mode`）：
   - `must_vote_roles`：所有 must_vote/has_veto 角色已提交
   - `all_reviewers`：所有评审人已提交
   - `vote_scope_roles`：投票范围内角色已提交
   - `publisher_only`：无额外要求
5. **通过规则校验**（`validatePassRule`）：
   - `rejectOnAnyVeto` + 结论为 pass 时：否决角色不能投 reject
   - `minPassVotes`：非发布人中至少 N 人投 pass 或 conditional_pass
6. **冻结快照**：全员投票快照写入 `based_on_votes`（65KB），生成快照编号 `DCP-RES-{时间戳36进制}`，不可覆盖

发起评审前，后端会用 ONES 解析出的规范项目 UUID 重新检查阶段唯一性和前置依赖。依赖使用创建时快照；旧草稿在首次发起时回填一次。只有已完成/已归档且当前轮决议为 `pass/conditional_pass` 的同类型阶段可满足前置条件。

材料上传地址、上传、删除、材料状态和指标更新共用证据编辑判定：`draft/ready` 可编辑当前轮，`remediation_pending` 可编辑下一轮工作副本，其余状态返回 `REVIEW_EVIDENCE_FROZEN`。

### 5.4 整改闭环

#### 整改流程

```
评审中 → 条件通过/否决 → 整改待处理(remediation_pending)
  → 创建/关联整改工作项 → 刷新状态 → 全部完成 → 确认整改
  → 发起复审(re_reviewing)
```

#### 工作项状态事件自动检测

`onIssueStatusChanged` 监听 `ones:project:issue-status:changed`：
1. 检查变更的工作项是否为某个评审单的整改项（`link_type === 'remediation'`）
2. 从 ONES 权威状态/状态分类更新 `dcp_linked_issue` 的校验字段
3. 检查该评审单的所有整改项是否均已完成，未知状态按未完成处理
4. 全部完成时通知发布人和创建者确认并发起复审

整改工作项不做字段、状态或删除锁定；`locked/locked_at/locked_by` 仅为升级兼容保留，不参与任何业务判断。

#### 权威状态检测方式

- **事件数据**：事件带有完整状态分类时直接校验并记录来源
- **服务端刷新**：确认整改和发起复审前通过 GraphQL 重新读取 ONES 状态；读取失败时返回 `REMEDIATION_STATUS_UNKNOWN`

### 5.5 评审撤回

`recallReview` 允许从 `reviewing` 状态撤回到 `draft`，受撤回配置约束：
- 撤回配置存储在 `dcp_base_config` key `review_recall_config`
- 支持时间窗口限制（发起后 N 小时内可撤回）
- 仅创建者可操作

### 5.6 统计报表

`getDcpStats` API 提供团队评审统计聚合数据：

| 数据维度 | 内容 |
|---------|------|
| 总览卡片 | 总评审数、评审中、已完成、关联工作项数 |

- **默认布局**（`DEFAULT_IPD_FLOW_LAYOUT`）：5 个阶段（concept/plan/develop/confirm/release）+ 11 个标记（DCP1-DCP5 菱形 + TR1-TR6 三角形）
- 存储在 `dcp_base_config` key `ipd_flow_layout`（JSON 字符串）
- 管理员通过模板配置页「IPD 流程图」Tab 可视化编辑阶段和标记位置
- 前端组件 `IPDFlowChart` 在评审详情中渲染流程图

### 5.8 文件附件管理

材料文件采用 ONES Object Storage + 实体引用双层方案：

| 层级 | 存储位置 | 内容 |
|------|---------|------|
| 对象存储 | ONES Object Storage | 文件二进制内容，object_key 格式 `dcp_files-{rid}-{tid}-{timestamp}` |
| 实体引用 | `dcp_review_material.file_data` | 存储 object_key，10MB 上限 |
| 元数据 | `dcp_review_material.file_name/file_size` | 文件名和大小 |

#### 上传/下载/预览流程

```
上传：前端获取预签名 URL → PUT 直传对象存储 → POST 通知后端记录 object_key
下载：前端获取预签名下载 URL → 浏览器直接下载
预览：后端代理 OPFetch 下载 → Buffer → base64 → 返回 { content, mime, file_name }
```

### 5.10 通知机制

系统通过 `@ones-op/node-ability` 的 `Notify` 函数发送通知，支持五种渠道：邮件、微信、钉钉、飞书、有度。

| 触发点 | 通知对象 |
|--------|---------|
| 发起评审 | 所有评审人 |
| 全部提交完成 | 决议人 |
| 发布决议 | 创建者 + 所有评审人（排除决议人） |
| 整改完成 | 发布人 + 创建者 |

通知为非阻塞调用，失败仅记日志。

## 6. 关键约束与已知限制

### 6.1 ONES 实体属性只能新增不能删除

实体属性一旦声明并部署，只能新增、不能删除或重命名。废弃字段保留在定义中，通过代码层忽略。

### 6.2 字段容量限制

| 字段类型 | 上限 |
|---------|------|
| text（常规） | ~64KB |
| text（file_data） | 10MB |
| text（快照字段） | 32KB |
| getMany() 每页 | 200 条 |

### 6.3 external API handler req 对象限制

`req` 对象不暴露标准 Express 的 `params`/`query`/`path` 属性，需通过 `getParam()` 函数从 `req.url` 正则提取。

### 6.4 Ones-Plugin-Id 头必须设置

- API 请求：`Ones-Plugin-Id: 709xehle`
- 权限检查：`Ones-Plugin-Id: built_in_apis`

### 6.5 其他已知限制

- 跨域 iframe 中 `window.parent.location` 不可访问，需从 URL hash 降级提取
- `plugin/list` 不返回 `mode:org` + `ProjectCustomComponent` 插件的 instance_id
- 对象存储 object_key 不支持 `/`，需用 `-` 替代
- 通知非阻塞，失败不重试
- 整改工作项不注册 TaskEventHandler，不限制工作项本身的正常编辑、状态变更或删除；整改闭环由独立状态事件和确认前权威刷新保证
