# DCP 评审中心 v2 — 需求方案

> 版本：v1.31.9
> 适用范围：ONES 团队级 DCP/TR 评审插件
> 文档状态：与代码同步（2026-07-23 基于 plugin.yaml v1.31.9 + 前端源码）

---

## 1. 业务背景

半导体行业 IPD（Integrated Product Development，集成产品开发）流程中，DCP（Decision Checkpoint，决策检查点）是关键的阶段性评审决策节点，用于评估项目是否满足进入下一阶段的标准。TR（Technical Review，技术评审）是阶段内的技术质量评审，关注技术方案和工程质量。

DCP 和 TR 的核心差异：
- **DCP**：商业投资决策（IPMT/Chair 主导），在阶段之间进行，结论为通过/有条件通过/不通过
- **TR**：技术质量决策（技术专家主导），在阶段内进行，结论含不通过/返工选项

传统评审依赖线下会议 + 文档传阅，存在以下痛点：
- 材料提交进度不透明，会议前难以确认完整性
- 评审意见分散在邮件/IM 中，难以汇总追溯
- 指标评估缺乏结构化记录，决策依据不清晰
- 决议结果无不可篡改的快照记录，事后争议无据可查
- 关联工作项（风险/缺陷/行动项）手动维护，易遗漏
- 整改项状态无法自动追踪，闭环管理缺失

DCP 评审中心插件在 ONES 项目管理平台上实现 DCP/TR 评审的全流程数字化管理，覆盖模板配置、评审发起、材料提交、多角色评审、决议发布、整改闭环、审计追溯全链路。

## 2. 核心业务概念

| 概念 | 说明 |
|------|------|
| **评审类型** | DCP（阶段决策评审）或 TR（技术评审），影响阶段模板、角色模板、决议规则 |
| **评审阶段** | DCP1~DCP5（概念决策→量产决策）；TR1~TR6（技术评审节点），阶段间可配置依赖关系 |
| **评审单** | 一次评审的实例，包含项目、阶段、标题、会议时间、状态、轮次 |
| **交付物材料** | 评审需要提交的文档/数据，按模板定义，标记必交/选交、负责角色 |
| **关键指标** | 量化评估指标，带黄线/红线阈值和风险颜色（绿/黄/红） |
| **评审人** | 按角色分配的评审参与者，含决议人（如 Chair）、IPMT 成员、技术专家等 |
| **决议快照** | 不可覆盖的评审结论记录，冻结全员投票结果，生成唯一快照编号 |
| **审计日志** | 全操作追溯记录，含操作人、动作、目标、结果、时间戳 |
| **Checklist** | 评审检查清单，按角色匹配，评审人逐项勾选 |
| **整改闭环** | 条件通过/否决后创建整改工作项，自动检测状态，全部完成后发起复审 |
| **评审轮次** | 评审可多轮进行，整改后发起复审产生新轮次，历史轮次数据保留 |
| **IPD 流程图** | 可视化展示 IPD 阶段流程和 DCP/TR 标记位置 |
| **决议规则** | 按 DCP/TR 分别配置：发布人角色、提交要求、允许结论、通过规则 |

## 3. 用户角色与权限

系统定义三个权限点，对应三类用户角色：

### 3.1 DCP 插件管理员（dcp_admin）

- **典型用户**：流程管理员、PMO
- **可执行操作**：
  - 配置阶段模板（DCP/TR 阶段、决议选项、决议模板、依赖关系）
  - 配置材料模板（材料名称、必交标记、负责角色、适用阶段、评审类型）
  - 配置指标模板（指标名称、单位、阈值类型、黄/红阈值）
  - 配置评审角色（角色名称、是否必投、是否否决、评审类型）
  - 配置 Checklist 模板（检查项文本、适用阶段、负责角色）
  - 配置决议规则（按 DCP/TR 分别配置发布人角色、提交要求、允许结论、通过规则）
  - 配置通知规则（触发点、通知渠道）
  - 配置 IPD 流程图（阶段布局、标记位置）
  - 配置评审撤回规则（时间窗口、权限）
  - 配置整改工作项类型

### 3.2 评审发起人（dcp_create_review）

- **典型用户**：项目经理、产品经理
- **可执行操作**：
  - 在项目内创建 DCP/TR 评审单（选择评审类型、阶段、标题、会议时间）
  - 编辑评审材料（上传/下载/预览/清除附件）
  - 编辑关键指标值
  - 配置评审人列表
  - 发起评审（草稿→评审中，三重校验）
  - 撤回评审（受撤回配置约束）
  - 复制评审单（草稿状态）
  - 催办评审人/决议人
  - 删除评审单（仅草稿状态、仅创建者）
  - 管理整改项（创建/关联/刷新状态/确认整改）
  - 查看评审详情全部 Tab

### 3.3 评审总览查看者（dcp_view_review）

- **典型用户**：部门负责人、PMO、所有相关方
- **可执行操作**：
  - 查看团队全部评审统计面板（含周趋势图、首轮通过率）
  - 按项目分组浏览评审列表
  - 多维度筛选（时间范围、阶段、项目）
  - 点击评审单查看完整详情
  - 复制评审编号和直链分享

> 注：评审人（被分配到评审单的用户）无需额外权限点，通过评审人工作台访问待办评审。

## 4. 功能需求

### 4.1 模板配置（dcp_admin）

管理员通过侧边栏「DCP评审中心 → 模板配置」进入全局模板配置页面，维护以下十类配置：

#### 4.1.1 阶段模板管理

- 新增/编辑/删除 DCP 或 TR 阶段
- 每个阶段配置：阶段代码（自动生成 DCP1/DCP2 或 TR1/TR2）、阶段名称、决议选项（JSON 数组）、决议模板文本、依赖关系（多选其他阶段）、评审类型（dcp/tr）、排序
- 决议选项示例：`["通过", "有条件通过", "不通过"]`
- 支持从预设选项中多选

#### 4.1.2 材料模板管理

- 新增/编辑/删除材料模板
- 每个材料配置：材料名称、适用阶段（多选）、是否必交、负责角色、评审类型、排序
- 创建评审单时，系统自动按所选阶段和评审类型带出适用材料模板

#### 4.1.3 指标模板管理

- 新增/编辑/删除指标模板
- 每个指标配置：指标名称、适用阶段、单位、阈值类型、黄线阈值、红线阈值、评审类型、排序
- 阈值类型：达标即通过 / 高于阈值预警 / 低于阈值预警
- 系统根据当前值和阈值自动计算风险颜色（绿/黄/红）
- 发起评审时校验：存在红线指标的，不允许发起

#### 4.1.4 评审角色管理

- 新增/编辑/删除评审角色
- 每个角色配置：角色名称、是否必须投票（must_vote）、是否有一票否决权（has_veto）、评审类型、排序
- 系统预置默认角色：Chair、研发VP、市场VP、财务代表、质量代表、供应链代表
- 发起评审时校验：所有 must_vote 角色必须已指定评审人

#### 4.1.5 Checklist 模板管理

- 新增/编辑/删除检查项
- 每个检查项配置：检查项文本、适用阶段、负责角色、评审类型
- 评审中状态时，评审人按角色匹配逐项勾选

#### 4.1.6 决议规则配置

按 DCP 和 TR 分别配置决议规则：
- **发布人角色**：指定谁有权发布决议（如 Chair）
- **提交要求模式**：
  - `must_vote_roles`：所有 must_vote/has_veto 角色须提交
  - `all_reviewers`：所有评审人须提交
  - `vote_scope_roles`：投票范围内角色须提交
  - `publisher_only`：无额外提交要求
- **允许的结论**：从 pass/conditional_pass/reject 中选择允许的选项
- **通过规则**：
  - `rejectOnAnyVeto`：否决角色投 reject 时是否阻止通过
  - `minPassVotes`：非发布人投 pass/conditional_pass 的最低人数

#### 4.1.7 通知设置

- 通知启用开关
- 四个触发点：发起评审时、全部评审人提交时、发布决议时、整改完成时
- 五种通知渠道：邮件(Email)、微信(WeChat)、钉钉(DingDing)、飞书(Lark)、有度(YouDu)

#### 4.1.8 IPD 流程图配置

- 可视化编辑 IPD 阶段流程
- 配置阶段：名称、形状（taper/rect）、宽度
- 配置标记：DCP1-DCP5（菱形，上方）和 TR1-TR6（三角形，下方），所属阶段、位置（0-1）
- 标记支持 reviewType 字段（dcp/tr）

#### 4.1.9 撤回配置

- 撤回时间窗口（发起后 N 小时内可撤回）
- 撤回权限设置

#### 4.1.10 整改配置

- 整改工作项类型配置
- 整改项状态同步方式

### 4.2 项目内评审工作台（dcp_create_review）

在项目页面内以页签形式展示，是创建和管理评审单的主入口。

#### 4.2.1 评审列表

- 分页展示当前项目的评审单（每页 5~15 条，按视口高度自适应）
- 列：编号、类型、阶段、标题、状态、资料进度、评审人进度、工作项数、会议时间
- 编号蓝色等宽字体，可点击复制编号+直链
- 标题可点击进入详情
- 顶部「+ 发起评审」按钮（需 dcp_create_review 权限）
- 「刷新」按钮
- IPD 流程图展示

#### 4.2.2 创建评审单

- 选择评审类型（DCP / TR）
- 选择评审阶段（从对应类型的阶段模板加载）
- 填写评审标题
- 选择计划会议时间
- 系统自动按阶段和类型带出适用材料模板和指标模板
- 创建后进入草稿状态，自动生成评审编号（格式：`{项目标识}{YYYYMMDD}{两位序号}`）

#### 4.2.3 评审详情（8 个 Tab）

**Tab 1：评审资料**

- 交付物清单表格：材料名称、责任角色、附件
- 必交材料用红色 `*` 前缀标记
- 进度格式：「已上传 X/Y」
- 草稿状态可编辑：选择文件、下载、清除
- 附件文件名可点击预览，下载按钮
- Office 文件不支持 iframe 预览，显示提示而非触发下载
- 下载用隐藏 `<a download>` 当前窗口触发

**Tab 2：关键指标**

- 指标表格：指标名称、当前值、单位、阈值、风险颜色（绿/黄/红背景色）
- 草稿/评审中状态可编辑指标值
- 系统自动计算风险颜色

**Tab 3：评审人与意见**

- 评审人表格：角色、评审人（显示姓名非 UUID）、结论、风险、意见、状态
- 草稿状态可编辑评审人列表（添加/删除评审人、分配角色）
- 评审中状态可查看各评审人提交的意见

**Tab 4：工作项**

- 展示评审单关联的 ONES 工作项列表
- 区分普通关联项和整改项（link_type: general/remediation）
- 可关联已有工作项、新建工作项、新建整改项
- 整改项支持刷新状态、同步状态
- 整改待处理状态时显示全部完成/部分完成统计
- 确认整改并发起复审

**Tab 5：Checklist**

- Checklist 清单，按角色匹配
- 评审中状态可勾选/取消
- 只读视图和可展开详情视图

**Tab 6：决议快照**

- 评审中状态 + 决议人角色可发布决议
- 决议结果：通过 / 有条件通过 / 否决
- 发布后冻结全员投票快照，生成唯一快照编号
- 决议不可覆盖
- 显示决议状态、发布人、发布时间

**Tab 7：审计日志**

- 全操作记录，按时间倒序
- 字段：时间、动作（中文）、详情、结果
- 展示前 20 条

**Tab 8：轮次对比**

- 多轮评审时对比各轮次的评审人意见和结果
- 展示历史轮次数据

#### 4.2.4 评审单操作

- 草稿状态：编辑材料/指标/评审人 → 发起评审（三重校验：必投角色已指定、必填材料已上传、关键指标无红线）
- 评审中状态：等待评审人提交意见 → 决议人发布决议 → 发布
- 撤回：评审中状态可撤回（受撤回配置约束）
- 催办：创建者可催办评审人或决议人
- 整改闭环：条件通过/否决后 → 创建整改项 → 自动检测状态 → 全部完成 → 确认整改 → 发起复审
- 已完成/已否决/已归档：只读
- 删除：仅草稿状态、仅创建者可操作
- 复制：草稿状态可复制（复制材料/指标/评审人）

### 4.3 评审人工作台

评审人通过顶部导航进入个人工作台。

#### 4.3.1 评审列表

- 待评审 / 已评审 Tab 切换
- 待评审列表：编号、项目、阶段、标题、状态、我的角色
- 已评审列表：额外显示我的结论（通过/有条件通过/否决）
- 支持深链接直达（`?review_uuid=xxx`）

#### 4.3.2 评审详情（评审人视角）

- **评审资料（只读）**：材料名称、责任角色、附件（预览+下载）
- **关键指标（只读）**：指标、单位、黄/红阈值、当前值、风险
- **我的评审意见**：
  - 结论（必填，不填充默认值，需手动选择）
  - 风险等级（低/中/高）
  - 意见摘要（结论为「有条件通过」或「否决」时必填）
- **其他评审人意见**：查看已提交的评审意见
- **Checklist**：按角色匹配的检查项，逐项勾选
- **关联工作项**：关联/新建工作项、整改项管理

### 4.4 团队评审总览（dcp_view_review）

通过侧边栏「DCP评审中心 → 评审总览」进入团队级全景视图。

#### 4.4.1 统计面板

- 统计卡片：全部评审、评审中、已完成、关联工作项
- 阶段分布图（柱状图/饼图）：按阶段分组的评审数和通过数
- 项目维度表：项目名称、评审数、完成数、通过数、通过率（颜色编码）
- 评审人统计：每位评审人的参评数、通过数、否决数
- 周趋势折线图：按周分组的评审数和通过数
- 首轮通过率：首轮已提交评审中通过的比例
- 所有图表和卡片可点击，进入下钻列表

#### 4.4.2 时间筛选

- 预设范围：本周/本月/本季度/本年/全部
- 自定义日期范围

#### 4.4.3 评审列表

- 按项目分组展示（可折叠/展开，默认折叠）
- 每组显示项目名称和评审单数量
- 组内列表列：编号、类型、阶段、标题、状态、资料、评审人、工作项、会议时间
- 支持排序
- 点击行打开评审详情

#### 4.4.4 评审详情

- 复用项目内评审工作台的 `ReviewDetail` 组件，8 个 Tab 全部可用
- 顶部「返回列表」按钮回到列表

#### 4.4.5 深链接直达

- 支持 URL 参数 `?review_uuid=xxx` 直接打开指定评审单
- 评审编号可复制（编号+链接到剪贴板）

## 5. 评审流程

### 5.1 状态流转

```
┌─────────┐     发起评审      ┌──────────┐   决议人发布决议   ┌──────────┐
│  草稿    │ ──────────────→ │  评审中   │ ──────────────→ │ 已完成   │
│ (draft) │  三重校验通过     │(reviewing)│  全员提交后      │(completed)│
└─────────┘                  └──────────┘                  └──────────┘
     │                            │
     │ 创建者可删除                │ 撤回(配置约束) → draft
     │ 可编辑全部内容              │ 评审人提交意见
     ▼                            ▼
                           ┌──────────────────┐
                           │ awaiting_resolution│
                           └────────┬─────────┘
                                    │
                    ┌───────────────┼───────────────┐
                    ▼                               ▼
          ┌──────────────────┐           ┌──────────────────┐
          │ 条件通过/否决      │           │ 通过              │
          │ remediation_pending│          │ → completed      │
          └────────┬─────────┘           └──────────────────┘
                   │
                   ▼ 创建/关联整改工作项
                   │ 状态事件检测 + 服务端权威刷新
                   ▼ 全部整改完成
                   │
                   ▼
     ┌────────────┐
     │ 发起复审    │
     │re_reviewing│
     └─────┬──────┘
           │
           ▼ 复审完成
     awaiting_resolution
```

### 5.2 各状态可执行操作

| 状态 | 发起人 | 评审人 | 决议人 |
|------|--------|--------|-------|
| **草稿** | 编辑全部、发起评审、撤回、复制、删除 | — | — |
| **评审中** | 查看详情、催办、撤回 | 提交评审意见、勾选Checklist、关联工作项 | 发布决议 |
| **整改待处理** | 创建/关联整改项、维护下一轮材料与指标、刷新状态、确认整改 | 查看详情 | 查看详情 |
| **复审中** | 查看详情 | 提交复审意见 | 发布复审决议 |
| **已完成** | 只读 | 只读 | 只读 |
| **已否决** | 只读 | 只读 | 只读 |

### 5.3 发起评审校验

1. **阶段前置校验**：使用创建时冻结的依赖快照；同一规范项目、同一评审类型的前置阶段必须已完成/归档，且当前轮决议为通过或有条件通过
2. **阶段唯一性校验**：创建和发起时均检查同阶段活动/已通过评审；历史重复草稿不能再次发起
3. **角色校验**：所有 `must_vote=true` 的角色必须已指定评审人
4. **材料校验**：所有 `required=true` 的材料必须已上传附件
5. **指标校验**：关键指标不能存在红线（risk_color=red）

评审进入 `reviewing/awaiting_resolution/re_reviewing` 后，材料、材料状态和关键指标作为投票依据冻结。整改期间可维护下一轮工作副本，写入 `round_no + 1`，上一轮决议快照不可覆盖。

### 5.4 决议发布规则

- 仅决议规则中配置的 `publisherRole` 角色可操作
- 按 `submitRequirement.mode` 校验提交完整性
- 按 `passRule` 校验通过条件（否决拦截、最低通过票数）
- 发布后冻结全员投票快照到 `based_on_votes` 字段
- 生成唯一快照编号 `DCP-RES-{时间戳36进制}`
- 决议不可覆盖，不可重新发布

### 5.5 整改闭环

1. 决议为条件通过或否决后，评审单进入 `remediation_pending` 状态
2. 发起人创建或关联整改工作项（link_type: remediation）
3. 系统通过工作项状态事件更新整改项状态，确认时由服务端重新读取 ONES 权威状态
4. 整改项全部完成后，通知发布人和创建者
5. 发起人确认整改并发起复审（re_reviewing）；任一整改项未完成或状态未知时均阻断
6. 复审产生新轮次（round_no +1），评审人重新提交意见

整改工作项本身不锁定，允许按 ONES 正常规则编辑和流转；插件只跟踪其完成状态。

### 5.6 评审撤回

- 仅评审中状态可撤回
- 受撤回配置约束（时间窗口、权限）
- 仅创建者可操作
- 撤回后回到草稿状态，可重新编辑

## 7. 非功能需求

### 7.1 数据存储

- 文件附件上限 10MB（object_key 存储于实体 `file_data` 字段，文件内容在对象存储）
- 文本字段上限 ~64KB（text 类型，最大 length 配置）
- 实体存储使用 cursor 分页查询（每页 200 条，安全上限 100 页）
- 父实体 JSON 快照兜底（reviewers_json、checklist_json、indicators_json、materials_json、_frozen），防子实体查询丢失
- 发起评审时冻结模板配置到 `_frozen`，确保评审进行中不受后续配置变更影响

### 7.2 审计与合规

- 全操作审计日志追溯，记录操作人 UUID、动作、目标、详情、结果、时间戳
- 操作人身份以后端网关提供的当前用户为准，不信任客户端传入的 operator_uuid
- 决议快照不可覆盖，冻结全员投票结果
- 整改项状态变更通过 `ones:project:issue-status:changed` 自动检测，确认复审前再次权威刷新

### 7.3 权限安全

- 三级权限控制：dcp_admin / dcp_create_review / dcp_view_review
- 前端权限验证通过 batch_check API（需 `Ones-Plugin-Id: built_in_apis` 头）
- 评审人通过评审人工作台访问，无需权限点分配

### 7.4 通知

- 非阻塞通知，通知失败不影响业务流程
- 四个触发点：发起评审、全部评审人提交、发布决议、整改完成
- 五种渠道：邮件、微信、钉钉、飞书、有度

### 7.5 性能

- 评审列表分页，每页 5~15 条按视口高度自适应
- 团队成员列表缓存（避免重复请求）
- 项目名称前端兜底补查（后端无法调页面 API）
- 统计报表支持时间范围筛选，避免全量扫描
