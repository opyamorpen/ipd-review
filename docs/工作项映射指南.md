# 工作项映射指南（评审单 → 工作项）

新架构下，评审单主体由**系统自定义工作项**承载：原生工作项详情页展示评审单基本信息（字段 + 状态），
插件自定义 Tab（「评审过程」）呈现评审全过程（评审人意见、材料、指标、Checklist、决议快照、状态轨迹）。
插件是评审状态机的唯一裁决方，工作项状态/字段是"镜像"；TaskEventHandler 守卫拦截绕过插件的手动修改。

本指南描述管理员从零完成映射配置的完整步骤。整体顺序：

```
第 1 步  在 ONES 标品后台创建自定义工作项类型 + 字段 + 工作流状态
第 2 步  在插件配置页「工作项映射」完成三步映射
第 3 步  创建一个评审单做端到端验证
```

> 数据源说明：类型/状态/字段三个团队级列表通过官方 OpenAPI 加载
> （`GET /openapi/v2/project/issueTypes|issueStatuses|issueFields`），
> 后端以**插件身份自动鉴权**（`FetchAsAdmin` + plugin.yaml 顶层 `oauth` 声明，平台内置 Oauth2AdminToken 能力），
> **无需配置任何凭据**（demo688 已实测：174 类型/229 状态/965 字段）。
> 极少数环境内置能力不可用时，可通过「工作项映射」底部的「流转传输配置（高级）」显式指定
> host/token 逃生。版本要求：三个列表接口需 ONES v3.14.117 / v3.15.26+（私有化 v7.x 均满足）。

---

## 第 1 步：在标品创建工作项类型

团队管理员在「配置中心 → 项目管理配置 → 工作项」操作。

### 1.1 创建自定义工作项类型

- 建议命名：**IPD评审单**（配置页会自动预选同名类型；命名不同也可，在插件里选它即可）；
- 一个类型同时承载 DCP/TR 两类评审，无需建两个；
- 创建后**启用到目标项目**。

### 1.2 在类型上创建自定义字段

| 字段名（建议） | 字段类型 | 选项 / 格式 | 级别 | 插件属性 key |
|---|---|---|---|---|
| 会议时间 | 日期 | — | **必配**（守卫冻结） | `meeting_time` |
| 评审轮次 | 整数 | 1,2,3… | **必配**（守卫冻结） | `round_no` |
| 评审结论 | 单选 | 通过 / 有条件通过 / 驳回 / 不通过 / 返工 | **必配**（守卫冻结） | `final_conclusion` |
| 评审阶段 | 单选 | DCP1 ~ DCP5、TR1 ~ TR6 | 建议 | `phase_code` |
| 评审类型 | 单选 | DCP / TR | 建议 | `review_type` |
| 评审编号 | 文本 | — | 可选（工作项自身编号已唯一） | `review_number` |
| 决议条件说明 | 多行文本 | — | 可选 | `condition_notes` |

按建议名创建时，插件端**零配置**（默认映射即上表）；字段名不同则到插件里改映射。
标题、负责人、创建人用工作项原生能力，无需建字段。
评审人意见/材料/指标/Checklist/决议快照由「评审过程」Tab 承载，不映射字段。

### 1.3 为类型配置工作流状态

在类型的流程配置中创建以下状态（名称建议与下表一致）：

| 评审状态 key | 中文名 | 说明 |
|---|---|---|
| draft | 草稿 | |
| ready | 就绪 | 可选：状态机包含但业务入口不经过，可不建 |
| reviewing | 评审中 | |
| awaiting_resolution | 待决议 | |
| resolution_published | 决议已发布 | |
| remediation_pending | 整改中 | |
| re_reviewing | 复审中 | |
| completed | 已完成 | |
| rejected | 已驳回 | |
| canceled | 已撤回 | |
| archived | 已归档 | |

**无需配置任何流转条件**：状态流转由插件评审流程驱动，通过镜像接口自动同步到工作项。

### 1.4 可选

- 整改工作项类型：在插件「整改设置」中配置（创建整改项时预填该类型）；
- 给工作项详情页手动添加「评审过程」Tab（LayoutCustomIssueTab 需管理员在项目/团队布局中添加）。

## 第 2 步：插件配置页完成映射

侧边栏「模板配置」→「工作项映射」（需管理员权限，点右上角「配置」进入编辑）：

1. **第 1 步 · 类型映射（必配）**：搜索并选择「IPD评审单」（或你创建的类型）。未配置时无法创建评审单；
2. **第 2 步 · 字段映射**：逐项确认 7 个属性映射到的字段名（输入框可直接下拉选择团队字段，并显示字段类型/是否匹配）；
3. **第 3 步 · 状态映射**：逐个评审状态选择对应的工作流状态（下拉选择；团队状态列表加载失败时可手填状态 UUID）；
4. 保存。顶部「配置完成度」会显示：类型 ✓ / 必配字段 N/3 / 状态映射 N/11。

## 第 3 步：端到端验证

1. 在项目中创建一个评审单 → 列表点击行应跳转到**原生工作项详情页**；
2. 检查工作项：标题 = `编号 标题`；阶段/类型/编号/会议时间字段已写入；状态 = 草稿对应的工作流状态；
3. 在插件内发起评审 → 工作项状态应变为「评审中」对应状态；
4. 发布决议 → 「评审结论」「决议条件说明」字段写入，状态同步；
5. 手动在工作项上修改会议时间/评审轮次/评审结论 → 应被拒绝，提示走「IPD评审操作」。

## 数据流说明（实现要点）

| 动作 | 插件行为 |
|---|---|
| 创建评审单 | `tasks/add3` 创建工作项（标题/项目/类型/负责人 + 按映射写入初始字段），add 意图放行守卫 |
| 修改会议时间/标题 | 插件存储更新 + 字段镜像写回工作项（update3，先登记意图防自锁） |
| 进入复审 | 轮次 +1 写回「评审轮次」 |
| 发布决议 | 「评审结论」「决议条件说明」写回；状态镜像 |
| 状态流转 | `pushStateMirror` 尽力同步（OpenAPI 优先，内部 GraphQL 兜底；未映射仅审计） |
| 手动改工作项 | 守卫（TaskEventHandler）拦截：新建该类型工作项、手动流转、修改三个必配字段、变更类型 |

所有写回均为**尽力模式**：失败写审计日志（评审单状态轨迹/审计 Tab 可见），不阻塞评审业务。
